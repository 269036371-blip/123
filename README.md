# KeyMacro-ayjy

> 一个 Windows 后台键盘连发宏：白名单按键**按下即发**、松开即停，支持多键同时连发。
>
> **Author: 霭阳霁月 (ayjy)**

---

## 它能做什么

- 白名单内的按键（默认 `1 2 3 4 5 C E R G J K`）**按下瞬间开始连发**，无启动延迟
- 支持**多键同时按住**，互不干扰
- 白名单外的按键（W/A/S/D、Ctrl/Alt 组合等）**完全透传**，不拦截
- 无窗口、托盘常驻、`F8` 开关、`Ctrl+Alt+F12` 退出
- **改键位不需要重新编译** —— 编辑 ini 后托盘点「重新加载配置」立即生效

## 快速开始

### 方式一：直接装（推荐，零环境）

1. 解压本仓库
2. 双击 `install.bat`（弹 UAC 点「是」）
3. 第 2 步选键位，**直接回车**用默认 `1 2 3 4 5 C E R G J K`
4. 桌面出现 `KeyMacro.exe`，双击运行

包内已内置预编译好的 `bin/KeyMacro.exe`（478 KB）。
它只依赖 `USER32 / WINMM / SHELL32 / KERNEL32` 和 Windows 10+ 自带的 UCRT，
**不需要 .NET、不需要 VC++ 运行库、不需要任何编译环境**。

### 方式二：手动编译

```bat
g++ -std=c++17 -O2 -municode -mwindows src\main.cpp -o KeyMacro.exe ^
    -luser32 -lwinmm -lshell32 -lwtsapi32 -static
```

MinGW-w64 或 MSVC 均可。若本机没有编译器，`install.bat` 会给出国内镜像的安装指引。

## 配置

配置文件位置（托盘右键 → 「打开配置文件」可直接打开）：

```
%APPDATA%\KeyMacro\KeyMacro.ini
```

### 键位

```ini
[keys]
list = 1 2 3 4 5 C E R G J K
```

空格或逗号分隔均可。支持：

- 单字母、数字：`q e r f 1 2`
- 功能键：`F1` `F5` `F24`
- 具名键：`SPACE` `TAB` `ENTER` `ESC` `UP` `DOWN` `LEFT` `RIGHT`
- 小键盘：`NUMPAD0` ~ `NUMPAD9`

**改完用托盘右键 → 「重新加载配置」生效，不用重启、不用重编。**

如果全部键位都无法识别或留空，程序会回退到默认键位而不是崩溃。

### 节奏参数

```ini
[timing]
interval_ms = 5     ; 连发间隔（毫秒）
press_ms    = 4     ; 单次"按下保持时长"（毫秒），自动收敛到 < interval_ms
hold_ms     = 0     ; 0 = 按下立即连发；若轻点一下触发两次，改成 100
```

**`press_ms` 不要删。** 零时长的 down+up 背靠背会被轮询式读输入的游戏
（DirectInput / Raw Input）整次漏掉，间隔越密漏得越多。
删掉它会出现"间隔调小反而更慢"的反常现象。

## 技术要点：为什么能做到 5ms

这是本项目在调试过程中最值得记录的一个发现。

### 问题

在部分 Windows 11 机器上，系统定时器被锁死在 **15.625 ms**。
此时 `timeBeginPeriod(1)` **不起作用**，`Sleep(1)` 实测仍然睡 15.6 ms：

```
纯 Sleep(1) 精度测试，200 次采样：
  平均 15606 µs
  最大 21004 µs
```

这意味着：把连发间隔设成 5 ms 或 1 ms 都毫无区别，实际都是 15.6 ms。
AutoHotkey 的 `SetTimer` / `Sleep` 只有这一条路，所以脚本语言在这类机器上撞死了天花板。

### 结论

Windows 上**至少有三条互相独立的定时器路径**：

| 路径 | 实测是否生效 |
|---|---|
| `timeBeginPeriod(1)` | ✗ 无效，仍锁 15.6 ms |
| `NtSetTimerResolution`（未文档化） | ✗ 无效 |
| `CreateWaitableTimerEx(HIGH_RESOLUTION)` | ✅ **有效，可达亚毫秒** |

微软在 Windows 11 上调整了 `timeBeginPeriod` 的行为，但
**高分辨率可等待定时器是另一套机制，不受影响**。
本程序用的就是第三条。

### 另一个关键点：不要用 `GetAsyncKeyState` 判断按键是否按住

看门狗若用 `GetAsyncKeyState(vk)` 判断物理按键状态，会周期性误判。
原因是**我们自己注入的 KEYUP 会把系统对该键的状态清成"松开"**：

```
t=0    发 DOWN → 系统状态：按下
t=4ms  发 UP   → 系统状态：松开   ← 物理键其实还按着
t=5ms  发 DOWN → 按下
```

"松开"窗口占每个周期的 `(interval - press) / interval`。
以 5 ms / 4 ms 为例是 **20%**。看门狗每 2 秒查一次，
按住 10 秒至少误判一次的概率约 **67%**，表现就是"长按过程中周期性顿一下"。

正确做法是记录**最后一次物理钩子事件**的时间戳（只由物理事件刷新，
注入事件不能刷新，否则钩子真死了也检测不到），再据此判断钩子是否存活。

## 已知现象：`.bat` 文件在 GitHub 网页上中文乱码

`install.bat` / `uninstall.bat` 使用 **GBK（代码页 936）** 编码。
Windows 的 `cmd.exe` 默认按 936 解析批处理文件，这是保证中文提示正常显示的必要做法。

代价是 GitHub 网页按 UTF-8 渲染这两个文件，中文会显示为乱码。
**这不影响使用** —— 下载到本地后，在 Windows 上打开与运行均正常。
请不要为了"修复"它而把文件转成 UTF-8，那会让命令行里的中文提示变成乱码。

其余文件（`README.md`、`LICENSE`、`src/main.cpp`、`*.ps1`）均为 UTF-8。

## 卸载

双击 `uninstall.bat`，四个选项：

| 选项 | 说明 |
|---|---|
| **[1] 只删程序**（推荐） | 删 exe、启动项、配置，保留编译环境 |
| [2] 程序 + 环境 | 额外删除 MSYS2（约 1–3 GB） |
| [3] 全部 | 再加 pacman 缓存与下载的安装包 |
| [4] 只删环境 | 保留程序 |

卸载前会结束正在运行的进程，程序退出路径会补发所有未释放的 KEYUP，
**不会留下"卡住"的按键**。

## 使用边界（请务必阅读）

本程序通过 `SendInput` 进行**系统级输入注入**。
默认 5 ms 间隔意味着每秒约 200 次注入事件，
而人类手指连点上限只有 8–10 次/秒。

**请勿在启用了反作弊的多人游戏中使用。**
EAC、BattlEye 等反作弊系统检测的正是这类输入频率的统计异常，
这不是调低参数就能规避的量级问题，而是"有反作弊就别用"的分类问题。

适用的正当场景包括：单机游戏、无障碍辅助输入、UI 自动化测试、
以及明确允许自动化输入的环境。

使用者需自行确保用途符合所在平台的用户协议与相关法律法规。
作者不对任何滥用行为负责。
